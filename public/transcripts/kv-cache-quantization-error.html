Fix: llama.cpp KV cache quantization error — invalid --ctk / --ctv parameters

by @0xRAGE.404 · Tech Solutions · Home

Problem

llama.cpp returns error: invalid option --ctk or unknown option --ctv when starting inference. Alternatively, the server starts but produces rapidly degrading quality at longer context lengths after setting cache type flags.

Cause

The --ctk (cache type for K) and --ctv (cache type for V) flags require specific values (q8_0, q4_0, q4_1, f16). Older llama.cpp builds use --cache-type-k / --cache-type-v syntax instead. Using an unsupported value or mixing incompatible quantization types with the model architecture causes silent corruption or startup failure.

Solution

Use the correct flag syntax and values for your llama.cpp version:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force Q8_0 KV cache quantization for audit VRAM budget\n# Newer syntax (llama.cpp b3000+):\n./main -m model.gguf -n 4096 --cache-type-k q8_0 --cache-type-v q8_0\n\n# Legacy syntax:\n./main -m model.gguf -n 4096 --ctk q8_0 --ctv q8_0

If the flags are not recognized, check the build version:

./main --version\n# If < b3000, use --ctk / --ctv\n# If >= b3000, use --cache-type-k / --cache-type-v

Step-by-Step Fixes

1Fix 1: Use Valid Cache Type Values

  1. Set `--ctk q8_0 --ctv q8_0` for balanced quality-speed.
  2. For higher compression, use `--ctk q4_0 --ctv q4_0` (more quality loss).
  3. Avoid `f16` for the cache type if VRAM is limited — it uses 2x the memory of q8_0.

2Fix 2: Fall Back to Default Cache

  1. Remove `--ctk` and `--ctv` flags entirely to use FP16 cache.
  2. If still failing, add `--memory-f16` to halve total cache usage.
  3. Try `--cache-type-k q8_0 --cache-type-v q8_0` (alternative syntax in newer builds).

FAQ

❯ What is KV cache quantization?

It compresses the key-value cache from FP16 to lower precision (q8_0, q4_0, q4_1), reducing VRAM usage by 30-50% with minimal perplexity impact.

❯ Which cache type is best for quality?

q8_0 strikes the best balance — ~1% perplexity increase for 50% memory reduction. q4_0 saves more memory but can degrade output quality noticeably.

❯ Does kv cache quantization affect inference speed?

Slightly — dequantization adds overhead. In practice, the VRAM savings allow larger batch sizes or longer contexts, often netting faster throughput.
