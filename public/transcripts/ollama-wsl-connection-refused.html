Fix: Ollama connection refused between Docker/WSL2 and Windows

by @0xRAGE.404 · Tech Solutions · Home

Problem

curl http://localhost:11434/api/generate returns Connection refused when ollama runs inside WSL2 or a docker container on WSL2, accessed from Windows.

Cause

WSL2 runs on a virtual network with its own IP. localhost from Windows does not map to WSL2 services by default unless the service binds to 0.0.0.0 or the WSL2 --net-host flag is used. Docker containers inside WSL2 also bind to the WSL2 VM's internal interface.

Solution

Bind Ollama to all interfaces inside WSL2:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force bind to all interfaces for cross-VM visibility\nollama serve --host 0.0.0.0

Or set environment variable:

export OLLAMA_HOST=0.0.0.0\nollama serve

Then from Windows, use WSL2's IP instead of localhost:

wsl -- hostname -I  # prints WSL2 IP, e.g. 172.x.x.x\ncurl http://172.x.x.x:11434/api/generate

Prevention

Add to ~/.bashrc inside WSL2:

export OLLAMA_HOST=0.0.0.0

For Docker, use --network host:

docker run --gpus all --network host -v ollama:/root/.ollama ollama/ollama

Reference

Microsoft WSL2 networking docs — "Accessing network applications".

FAQ

❯ Why doesn't localhost work from Windows to WSL2?

WSL2 uses a virtual network with its own IP. Windows localhost does not forward to WSL2 services by default.

❯ Does --network host fix Docker within WSL2?

Yes — `docker run --network host` makes the container use the WSL2 VM's network stack directly.

❯ Is 0.0.0.0 safe for production?

No — it exposes Ollama to all network interfaces. For production, bind to the specific WSL2 IP and use a firewall.
