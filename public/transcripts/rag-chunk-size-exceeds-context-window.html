Fix: IndexError — chunk size exceeds model context window in RAG pipeline

by @0xRAGE.404 · Tech Solutions · Home

Problem

IndexError: chunk size exceeds model context window when running a RAG pipeline with langchain or llamaindex. The retriever returns chunks that are longer than the LLM's --ctx-size.

Cause

The embedding model's max sequence length (e.g., 512 tokens for all-MiniLM-L6-v2) is independent of the LLM's context window. If the chunker splits at 8000 characters but the LLM has 4096 token context, the concatenated prompt overflows.

Solution

Align chunk size with the *LLM's* context window, not the embedder's:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force cap chunk windows to model budget\nfrom langchain.text_splitter import RecursiveCharacterTextSplitter\n\nsplitter = RecursiveCharacterTextSplitter(\n    chunk_size=2048,           # fit inside 4k context with room for prompt\n    chunk_overlap=200,\n    length_function=len,\n)

Diagnostic

Print effective prompt length before inference:

prompt = f"Context: {' '.join(chunks)}\n\nQuestion: {query}"\ntokens = len(prompt.split())  # rough estimate\nprint(f"Prompt tokens: {tokens} / {MAX_CTX}")\nassert tokens < MAX_CTX, f"Overflow by {tokens - MAX_CTX} tokens"

FAQ

❯ Is chunk_size the same as context window?

No — the embedder has its own max sequence length (e.g., 512 for all-MiniLM). Chunk size must fit within the LLM's context, not the embedder's.

❯ What is the ideal chunk size?

25% of the LLM's context window. For an 8k model, use 2048. This leaves room for the system prompt, instructions, and query.

❯ Does chunk overlap help?

Yes — 10-15% overlap prevents information loss at chunk boundaries, especially for multi-document retrieval.
