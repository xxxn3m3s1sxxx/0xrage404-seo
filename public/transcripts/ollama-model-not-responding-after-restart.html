Fix: Ollama model not responding after Docker restart

by @0xRAGE.404 · Tech Solutions · Home

Problem

After a docker restart or host reboot, ollama list shows the model but ollama run hangs or returns a connection error.

Cause

ollama's container mounts a GPU acceleration layer (CUDA/ROCm) that does not survive container restart without explicit device re-registration. The Ollama server process starts but cannot access the GPU, falling into a deadlock on inference.

Solution

Recreate the container instead of restarting:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force GPU re-registration on container start\ndocker compose down ollama\ndocker compose up -d ollama\nollama pull <model> # re-pull if model state is corrupted

If models persist (bind-mounted /root/.ollama), this preserves them:

docker compose down ollama\ndocker compose up -d ollama\nollama list # should show models; run works after ~5s warmup

Root Cause

docker's --gpus all flag binds the device at docker run time. A docker restart re-uses the old bindings, which may point to stale file descriptors after a driver reload.

Prevention

Add a healthcheck to your docker-compose.yml:

healthcheck:\n test: ["CMD", "ollama", "list"]\n interval: 30s\n retries: 3\n start_period: 10s

FAQ

❯ Why does docker restart break Ollama?

Docker's --gpus all flag binds the device at run time. A restart re-uses stale file descriptors after driver reload.

❯ Can I preserve downloaded models across restart?

Yes — bind-mount /root/.ollama as a volume. Models persist but inference may fail until GPU re-registration.

❯ Does Ollama need --gpus all?

Yes — without GPU access, Ollama falls back to CPU-only mode which may deadlock on GPU-optimized models.
