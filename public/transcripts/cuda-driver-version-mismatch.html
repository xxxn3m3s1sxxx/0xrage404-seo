Fix: CUDA driver version is insufficient for CUDA runtime version

by @0xRAGE.404 · Tech Solutions · Home

Problem

llama.cpp or torch fails to initialize the GPU with: CUDA driver version is insufficient for CUDA runtime version.

Cause

The installed NVIDIA driver is older than the CUDA toolkit version the binary was compiled against. The driver exposes a maximum CUDA version via nvidia-smi; if the runtime (e.g., PyTorch's bundled CUDA) expects a newer one, initialization fails.

Solution

  1. Check versions: nvidia-smi (driver) vs nvcc --version (toolkit).
  2. Update the NVIDIA driver to at least the minimum required by your CUDA toolkit.
  3. On WSL2, update the windows host driver package — not inside WSL.

Step-by-Step Fixes

1Update NVIDIA driver to match CUDA toolkit

  1. Check your driver and runtime versions: nvidia-smi shows the driver version, nvcc --version shows the toolkit version.
  2. If driver < toolkit minimum, download the latest driver from NVIDIA.com for your GPU.
  3. After install, reboot or run: sudo nvidia-smi -pm 1 to reinitialize the driver.
  4. Verify with: nvidia-smi | grep 'CUDA Version'

2Use docker with matching CUDA image

  1. Instead of updating the host driver, pin your container to a compatible CUDA version: FROM nvidia/cuda:12.4.0-runtime-ubuntu22.04
  2. This isolates the CUDA runtime from the host driver.
  3. Run with: docker run --gpus all --rm myimage nvidia-smi

3Set CUDA_VISIBLE_DEVICES to bypass check (temporary)

  1. For llama.cpp specifically: export CUDA_VISIBLE_DEVICES=0
  2. Or set LD_LIBRARY_PATH to point at the correct libcuda: export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH
  3. This is a workaround, not a fix — update your driver.

FAQ

❯ Why does nvidia-smi show a different CUDA version than nvcc?

nvidia-smi shows the maximum CUDA version your driver supports. nvcc shows the CUDA toolkit version installed. They do not need to match exactly — the driver only needs to be >= the toolkit version.

❯ Do I need to reboot after updating the NVIDIA driver?

Yes, on Linux run sudo reboot or at minimum sudo nvidia-smi -pm 1 to reactivate the persistence daemon. On WSL2, run wsl --shutdown from PowerShell and restart WSL.

❯ This error appears only inside Docker. Why?

The container has a different CUDA toolkit than the host driver supports. Use a container image whose CUDA version matches your host driver, or update the host driver.
