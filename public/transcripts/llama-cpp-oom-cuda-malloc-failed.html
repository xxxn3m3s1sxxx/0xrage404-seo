Fix: llama.cpp CUDA_ERROR_OUT_OF_MEMORY on model load

by @0xRAGE.404 · Tech Solutions · Home

Problem

llama.cpp throws CUDA_ERROR_OUT_OF_MEMORY when loading a 30B+ parameter model, even though nvidia-smi shows free VRAM.

Cause

CUDA memory fragmentation or insufficient context-size headroom. The allocator sees free pages but cannot satisfy the contiguous allocation for the model weights + kv cache.

Solution

Reduce VRAM pressure at model load:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force conservative memory mapping for audit-mode\n./main -m model.gguf -n 128 --n-gpu-layers 0 --memory-f16

If that works, gradually increase --n-gpu-layers until the OOM returns. The exact layer count depends on your GPU's VRAM and the model's quantization level.

If you're also hitting OOM at higher context lengths, check Fix: llama.cpp OOM when context size exceeds 8k tokens.

See llama.cpp memory_mapping.h for the allocator internals. The --memory-f16 flag halves KV cache memory usage at the cost of slightly higher GPU-CPU transfer overhead.

  1. Switch from Q6_K to Q4_K_M.

2Fix 2: Memory Mapping

  1. Disable `mmap` if running near OOM limits.
  2. Use `--memory-f16`.

FAQ

❯ What is cudaMalloc failure?

It means the GPU allocator cannot reserve a contiguous block of memory for the tensor data.

❯ Does nvidia-smi show accurate free memory?

Not always — CUDA fragmentation can show free pages but no contiguous block large enough.

❯ Can I split the model across multiple GPUs?

Yes, use `--tensor-split` to distribute layers across GPUs, but this requires multi-GPU setup.
