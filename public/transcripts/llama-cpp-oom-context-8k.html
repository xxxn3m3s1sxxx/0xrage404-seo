Fix: llama.cpp OOM when context size exceeds 8k tokens

by @0xRAGE.404 · Tech Solutions · Home

Problem

llama.cpp runs out of memory when --ctx-size is set above 8192, even with a quantized model that fits comfortably at lower context lengths.

Cause

The kv cache grows quadratically with context size. At 8192 context, a 70B model in Q4_K_M needs ~24 GB just for the cache. At 16384 it doubles again. The allocator cannot find a contiguous block for both model weights and KV cache buffers.

Solution

Calculate your VRAM budget before setting context size:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Budget: model(10GB) + cache(16GB @ 8k) = 26GB on 24GB card -> OOM\n./main -m model.q4_k_m.gguf -n 4096 --memory-f16 --n-gpu-layers 35

KV cache memory ≈ n_layers * n_ctx * d_model * 2 * 2 bytes. Half it with --memory-f16.

Fix: llama.cpp CUDA_ERROR_OUT_OF_MEMORY on model load.

Step-by-Step Fixes

1Fix 1: Reduce context window (n_ctx)

  1. Set `--n-ctx` to 4096 instead of 8192.
  2. Check VRAM usage with `nvidia-smi`.

2Fix 2: Offload Layers (n_gpu_layers)

  1. Reduce `--n-gpu-layers` to force CPU fallback for KV cache.
  2. Enable `--flash-attn` if supported by the model.

FAQ

❯ Why does 8k context crash my GPU?

The KV cache size grows quadratically with context length. 24GB is often insufficient for 8k on 30B+ models.

❯ Does --memory-f16 help with OOM?

Yes, it halves KV cache memory usage at the cost of slightly higher GPU-CPU transfer overhead.

❯ Can I use context shifting instead of reducing context?

Yes, `--rope-scaling` with context shifting fits longer context without proportional memory growth, but requires model support.
