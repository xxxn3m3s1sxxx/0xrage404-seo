Fix: ValueError — expected embedding dimension 1536 but got 768 in RAG

by @0xRAGE.404 · Tech Solutions · Home

Problem

ValueError: expected embedding dimension 1536 but got 768 when querying a ChromaDB or faiss vector store. The collection was built with OpenAI text-embedding-ada-002 (1536 dims), but the query uses a local model like all-MiniLM-L6-v2 (384 dims) or BAAI/bge-large-en (1024 dims).

Cause

Vector databases enforce dimension consistency across all embeddings in a collection. Switching the embedding model mid-project without rebuilding the index causes dimension mismatch.

Solution

Rebuild the collection with the new embedding model:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force dimension alignment for audit vector index\nimport chromadb\n\nclient = chromadb.PersistentClient(path="./chroma_db")\nclient.delete_collection("my_docs")  # nuke old index\ncollection = client.create_collection(\n    name="my_docs",\n    metadata={"hnsw:space": "cosine"}\n)\n\n# Re-embed all documents with the new model\nfrom sentence_transformers import SentenceTransformer\nmodel = SentenceTransformer("all-MiniLM-L6-v2")  # 384 dims\n\nembeddings = model.encode(documents).tolist()\ncollection.add(embeddings=embeddings, documents=documents, ids=ids)

FAQ

❯ Does changing the model break indices?

Yes, embedding vectors are model-specific. You cannot mix them.

❯ Can I convert between dimensions?

No — you must re-embed all documents with the target model. Dimensionality reduction (PCA) is not recommended for retrieval.

❯ What dimension should I use?

OpenAI ada-002 uses 1536, all-MiniLM-L6-v2 uses 384, BGE-large uses 1024, BGE-M3 uses 1024. Pick once and pin it.
