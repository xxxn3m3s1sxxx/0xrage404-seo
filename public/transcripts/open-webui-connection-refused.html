Fix: Open WebUI connection refused to Ollama backend

by @0xRAGE.404 · Tech Solutions · Home

Problem

Open WebUI loads but shows "connection refused" or "Failed to connect to ollama backend". The Ollama server is running and reachable via curl, but the web UI cannot establish a connection.

Cause

Open WebUI (running in a browser or docker container) tries to reach Ollama at http://localhost:11434. If Ollama runs in a separate Docker container, localhost resolves to the Open WebUI container's own network namespace, not the Ollama container. Even on bare metal, if Ollama binds to 127.0.0.1 and the browser uses localhost resolving to ::1 (IPv6), the connection fails.

Solution

Run both services in the same Docker Compose stack:

Step-by-Step Fixes

1Fix 1: Unify Docker Network

  1. Place both Ollama and Open WebUI on the same Docker network.
  2. Use `docker compose` with a shared network definition.
  3. Set `OLLAMA_HOST=http://ollama:11434` in Open WebUI env.

2Fix 2: Bind Ollama to 0.0.0.0

  1. Set `export OLLAMA_HOST=0.0.0.0` for the Ollama container.
  2. restart Ollama and verify with `curl http://localhost:11434/api/tags`.
  3. If in WSL2, use the WSL2 IP instead of localhost (see ollama-wsl-connection-refused).

FAQ

❯ Why does Open WebUI use localhost instead of the Docker service name?

By default, Open WebUI targets `http://localhost:11434`. Inside a container, localhost refers to its own namespace, not the Ollama container.

❯ Can I use Open WebUI without Docker?

Yes — run Ollama natively on the host and set `OLLAMA_HOST=0.0.0.0`. Then Open WebUI (also natively or in Docker) can reach it via the host IP or `host.docker.internal`.

❯ Does Open WebUI need CORS config?

Not for same-origin setups. For cross-origin (different domains), set `OLLAMA_ORIGINS=*` on the Ollama server.
