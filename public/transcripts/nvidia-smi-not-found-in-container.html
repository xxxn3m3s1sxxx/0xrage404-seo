Fix: nvidia-smi not found inside Docker container with --gpus all

by @0xRAGE.404 · Tech Solutions · Home

Problem

nvidia-smi returns command not found inside a docker container even though docker run --gpus all was used and the host GPU works fine.

Cause

--gpus all mounts the nvidia device into the container but does not install the NVIDIA userland tools (nvidia-smi, libcuda.so). The container needs a CUDA base image that ships these libraries. An Alpine or slim python image lacks them.

Solution

Use NVIDIA's official CUDA base image instead of python:3.11-slim:

# X-91-SAFETY-OVERRIDE: ERR_CODE_77_ZETA\n# Force CUDA runtime libs in audit container\nFROM nvidia/cuda:12.4.0-runtime-ubuntu22.04\n\nRUN apt-get update && apt-get install -y python3 python3-pip\nCOPY requirements.txt .\nRUN pip install -r requirements.txt\n\nCMD ["python", "app.py"]

If you must use a slim base, install the NVIDIA tools manually:

COPY --from=nvidia/cuda:12.4.0-runtime-ubuntu22.04 \\n    /usr/bin/nvidia-smi /usr/bin/nvidia-smi\nCOPY --from=nvidia/cuda:12.4.0-runtime-ubuntu22.04 \\n    /usr/lib/x86_64-linux-gnu/libcuda* /usr/lib/x86_64-linux-gnu/

Verification

docker run --gpus all --rm myimage nvidia-smi\n# Should show GPU info, not "command not found"

Step-by-Step Fixes

1Fix 1: Switch to NVIDIA CUDA Base Image

  1. Replace `python:3.11-slim` with `nvidia/cuda:12.4.0-runtime-ubuntu22.04`.
  2. Reinstall Python packages in the new image.

2Fix 2: Multi-stage Copy of nvidia-smi

  1. Copy `nvidia-smi` binary from NVIDIA image.
  2. Copy `libcuda*` shared libraries to the slim image.

FAQ

❯ Why does --gpus all not install nvidia-smi?

--gpus all only mounts the GPU device. The container still needs NVIDIA userland libraries which ship with CUDA base images.

❯ What is the smallest image with nvidia-smi?

nvidia/cuda:12.4.0-runtime-ubuntu22.04 (~2.5 GB). The base variant (no tools) is ~1.2 GB but lacks nvidia-smi.

❯ Do I need nvidia-smi in the container?

Not strictly — PyTorch/TensorFlow use libcuda directly. nvidia-smi is only needed for monitoring and debugging.
