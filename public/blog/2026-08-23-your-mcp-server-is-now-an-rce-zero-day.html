Your MCP server just became a remote code execution backdoor. And the worst part? Its own trust model waved the attacker through.

GitLab's Threat Research Group dropped a critical finding on August 17th: Serena — "the IDE for your agent," 27,000 GitHub stars, 136,000 downloads every single month — executed attacker code the moment a developer opened a repository. The weapon was a poisoned .serena/project.yml tucked into an innocent-looking repo. Clone it, open it with Serena, and arbitrary code runs on your machine with your full user privileges.

Here is the part that should make you furious. Serena HAD a trust model. trusted_project_path_patterns blocked shell commands on untrusted repos — exactly the feature designed to stop this exact attack. But the template injection path never checked is_trusted(). A protection mechanism failure, CWE-693 in the flesh: the front door locked, the window wide open. User text flowed straight into a Jinja2 renderer with no sandbox. This vulnerability class is older than some of the people reading this.

TACTICAL DEBRIEF: MCP servers run with everything you can touch. Treat every one of them like privileged access — because that is what they are. Update to serena-agent 1.7.0 today. And before you wire any new MCP tool into your workflow, ask the vendor one question: how do you handle untrusted repository inputs? If they hesitate, you have your answer.

The npm ecosystem needed a decade of incidents to grow security patterns. MCP gets no decade.
