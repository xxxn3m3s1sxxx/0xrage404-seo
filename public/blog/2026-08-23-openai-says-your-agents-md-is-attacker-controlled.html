OpenAI just classified your AGENTS.md file as attacker-controlled input. The file sitting in your repository right now. The one your team treats as documentation.

This came out of the Snowflake-adjacent Black Hat research, but the implications hit every repo on GitHub. Here's the mechanics. OpenAI's Codex runs multi-pass workflows: pass one does work, and if the output fails validation, pass two fires automatically in the same checkout. Researchers at Novee Security realized pass one can write to AGENTS.md — Codex's own instruction file, loaded from disk on every invocation and treated as authoritative context. Not protected like .git or .codex directories. Just a markdown file any process can rewrite.

So the attack is trivial: get attacker-controlled content into the first pass — an issue body, a PR description, anything the agent reads — make that pass fail schema validation on purpose, and the second pass launches with your instructions injected into its system prompt. Agent hijacking via the config file you wrote yourself.

OpenAI's response tells you everything about where we are. No CVE. No patch. Their position: this is documented, intended sandbox behavior. They hardened their own repository within three days — separated passes into different jobs, clean checkouts, drop-sudo, read-only sandbox — and updated their security documentation to list AGENTS.md and AGENTS.override.md as untrusted input surface.

Read their guidance twice. The vendor is telling you that the file most teams skim past because it's "just project config" should be reviewed as executable instructions on any checkout containing untrusted code. Forks. Issue-triggered runs. Outside pull requests. If the checkout isn't fully trusted, neither is anything the agent reads from it.

And they're right, because this pattern generalizes far beyond Codex. The same research found Gemini CLI parsing allowlists at registration but never enforcing them at execution. Found Claude Code's validator marking values safe before a more privileged layer acted on them. One shape repeating across every harness: something marks a value as safe, something else trusts that mark with higher authority, and nothing re-verifies provenance in between.

Your AGENTS.md is not documentation anymore. Treat it like a shell script that runs whenever an AI visits your repo. Because now, functionally, it is.
